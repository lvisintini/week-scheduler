# Events

- **R-EVT-01** **[U]** Rounded boxes with a background colour, like Google Calendar. Created by dragging on empty space of a day (a plain click/short drag creates a 1-hour event) **[C✓]** or with the **+** toolbar button **[U]**. Can be removed, moved up/down within a day, moved to other days, resized, and may overlap other events.
- **R-EVT-02** **[U]** Fields: title (required), description (optional), an **owner** (optional, R-EVT-20), the default **persons involved** (multi-select of our people; a day can have its own list, R-EVT-21), colour, and **at least one schedule**; each repetition has its own times, the person who **performs** it (its *responsible person*: the owner by default) and timing (R-UI-07). Toggling a schedule shows/hides its events.
- **R-EVT-03** **[U]** **Event box layout (rows):** row 1 = responsible person's icon (only if there is one, just before the title, sized to the text) + title on the left, the **time range right-aligned**, then the status icons (activity type / repeat / ⚠ / lock, top-right, R-EVT-04; **[U]** unchanged); row 2 = `By: <responsible name>` (no icon, left) and, right-aligned on the same row, `With: <involved people with icons>`; **no description row — the description is never shown in the compact grid view (event boxes, print schedule, print day view); it appears only in the peek card, the agendas and the dialog [U]**. Person icons inside event boxes are small (10 px glyph on a white disc) **[U]**. Continuation pieces show `from Fri 22:00 · until 02:00` as their time. **The title wins over the time** **[U]**: when the title is cut short while the time range shares row 1 (narrow lanes, a phone's day view), the time moves to the start of row 2 (row 2 created if needed), and if row 2 then doesn't fit it is dropped like any By/With row (⋯).
- **R-EVT-04** **[U]** Status icons top-right of the box: the **activity type icon** (R-EVT-11), **repeat icon** (event has >1 repetition), **[C✓]** ⚠ (repetitions of this event overlap and clash, R-REP-05), lock icon (locked).
- **R-EVT-05** **[U]** **Clipping:** event boxes render the *By/With* row only if it fits completely (`fitAll`: every box of a redraw is measured after layout before any is changed, the boxes whose time moves to row 2 (R-EVT-03) are measured again all together, then all are changed: two layouts per redraw at most, not one per box; otherwise it is dropped). When anything is hidden (that row dropped or the title ellipsised) the box shows a small **⋯** marker plus a faint bottom fade. **[U]** **Peek card** (mouse hover ~0.35 s over an event, locked ones included — hit-tested at column level, up to 3 stacked overlapping events): title (colour chip, responsible icon), time, `By: …`, `With: …` (icons), full description, schedules, ⚠ and lock notes, then a gap and the UI-behaviour instruction lines (for repeating events: "Dragging changes all repetitions; hold Shift to change only this one."; the number of repetitions is deliberately not shown). There is no native tooltip (events keep an `aria-label`); the peek card is hover-only — on touch a tap opens the dialog, which shows everything.
- **R-EVT-06** **[U]** Dialog **Delete** is a single button: removes the whole event including all repetitions and closes the dialog (no confirmation, no "delete all repeats" wording).
- **R-EVT-07** **[U]** **Copy** lives in its own dialog (opened by the "Copy…" button of the event dialog, or by **right-click** on the grid **[C✓]**): choose destination schedule and colour (same colour / same hue brighter-or-darker / random / chosen). Default: tweak when the destination already contains the event, otherwise same colour **[U]**. A copy is an independent event (to share one event, tick several schedules) — the dialog says so **[C✓]**.
- **R-EVT-08** **[U]** Event opacity = highest opacity among its visible schedules.
- **R-EVT-11** **[U]** **Activity type:** each event has **at most one** activity type (`type` = a type id, stored only when set), for the **whole event** (not per repetition) **[U]** — one type per event so a later per-person statistics view can put every minute in exactly one bucket. Dialog: an *Activity type* list (`#fTy`, `(none)` first, then the workspace's types; the chosen type's icon is shown beside it). The type's **icon is the first status icon** on every box (R-EVT-04); peek card, agenda and `aria-label` name it (icon in the type colour). Boxes keep the **event's own colour** — the type colour is for statistics, and on the grid only for repetitions whose colour is set to *Activity type colour* (R-EVT-22) **[U]**. A type with the **soft look** (default: Free time) draws its events as free time was drawn before **[U]**: a soft tint of the event colour (`color-mix` with `--card`, follows light/dark, prints light), a solid 4 px colour edge on the left, dark text without shadow. Otherwise typed events behave like any event — **the overlap rules (R-EVT-09/10) do not change [U]**. Phases never carry a type **[U]**.
- **R-EVT-12** **[U]** **Flexible time** (name chosen over "tentative", which calendars use for "maybe/unconfirmed" **[U]**): the activity happens *around* the given times but may not take the whole slot. Stored **per repetition** (`slot.flex:true`, only when set) **[U]**. Dialog: one of the three choices of each time's own **Timing** list (R-EVT-15, R-UI-07). Drawn with a **2 px dashed border** **[U]** (light on dark colours, dark on light ones via `ink()`, a darker shade of the colour on soft-look boxes). Peek card, agenda and `aria-label` say *Flexible time (around these times)*. Independent of the activity type (it's about *when*, not *what*). Phases never have it. **Overlap rules do not change [U]**; drags keep the marks.
- **R-EVT-15** **[U]** **Flexible start/end** (*Inicio/fin flexible*): a task that may start a bit late and/or finish a bit early (e.g. work 09:00–17:00, fine to start any time until 09:30 and to wrap up from 16:45).
  - **Model [U]:** per repetition, `slot.fs` = flexible minutes *after the start*, `slot.fe` = flexible minutes *before the end* (15-min steps, stored only when > 0). The slot's `start`/`end` stay the **outer** times, so moving, past-midnight pieces and hidden-hour counting are unchanged. **Core** = `start+fs` … `end−fe`; the parts outside it are the **margins**. **[C✓]** The core stays ≥ 15 min (shrinks the end margin first, then the start margin); `parseData` snaps and clamps; the dialog refuses a save that would break it, naming the day. Phases never have margins.
  - **Both kinds of flexible time are kept [U]**, as one per-repetition choice: each time's **Timing** list (*Horas* in Spanish — not *Horario*, which is the word for schedule): **Fixed** / **Flexible start/end** / **Around these times** (R-EVT-12); mutually exclusive (`parseData` drops `fs`/`fe` on a `flex` slot). Choosing *Flexible start/end* shows, on a line of its own under that day, *May start up to [list] late, and finish up to [list] early* (0, 15, 30, 45 min, 1 h, 1 h 15, 1 h 30, 2, 2½, 3, 4 h; 15/15 by default); a margin of 0 is not stored, both 0 = fixed. There is **no event-level timing** (**Rejected:** an event-level *Timing* switch that only set every day, with a per-day toggle and popover: an event-level look-alike) **[U]**; the day's ⧉ button copies its timing to the other days.
  - **Drawing [U]:** the core is a normal solid box; the margins (children of the day column in the event's lane) continue it above/below with a **2 px dashed border in the event colour**, no border towards the core, and a **translucent tint** (30 %, 14 % for soft-look types); only the outer corners are rounded. **[C✓]** The **text sits in the core box** (**Rejected:** at the top of the whole window): the core must be drawn above every margin, so the text has to live in the core. A piece that is **all margin** (e.g. the part after midnight of an event whose end margin covers it) is drawn as a dashed box with the text. The time shown is the outer range (`09:00–17:00`); peek card, agenda and `aria-label` add *Start between 09:00 and 09:30 · Finish between 16:45 and 17:00*. The resize handle sits at the outer end; dragging a margin moves the event.
  - **Overlaps — only cores count [U]:** stripes (R-EVT-09) and the repetition ⚠ (R-REP-05, `overlapSet` via `ivs`) appear only where **core overlaps core**. **Side-by-side lanes use core times too [U]:** occurrences that touch only through margins are not in the same lane group, so both keep the full column width (**Rejected:** 15 flexible minutes putting a parallel event side by side, at half width, for its whole length). Margins follow their event's lane. **Exception: a piece that is all margin** (e.g. the evening part of a sleep whose core starts at midnight) is the box with the text, so it takes a lane by **its own window** like a core would **[U]** (e.g. three people's sleep, one of them with a 1 h 30 flexible start, should be three lanes late in the day, not one full-width box over the other two); it still never makes stripes.
  - **Drawing order [U]:** every margin is inserted **before every core box** in the day column (after the hour lines), so a core always covers the margins of other events — **hidden entirely, dashed outline included**. Margin on margin: the tints mix, each keeps its dashed edges, the later-starting one on top (fallback if it ever looks messy: show only the top margin's tint there). **Hit-testing**: where a core is under the pointer, only cores count — a core over a margin opens/drags/peeks the core's event directly; margins alone behave like any overlap (chooser). Known side effect: resize handles stay above every box (bug 6 in `../known-issues.md`), so the last ~9 minutes of an event's window still grab its handle even where another core covers its end margin.
  - **Statistics [U]:** margins count as **planned** time and are added to the hatched *of which flexible* part. **[C✓]** Double-booked time: a core beats a margin (the core's event gets that time); margin vs margin is split evenly; the *Overlapping* line and its places count only core on core.
  - **Dragging [C✓]:** moving keeps the margins; resizing (also "all repetitions" and *Only this day*) keeps their lengths, shrinking them if the core would drop below 15 min. Dragging the core's own edges may come later.
- **R-EVT-16** **[U]** **Involved people only on call** (`event.oncall:true`, only when set; per event, like `involved`): the involved people are *available, not busy* — e.g. Ann at hand to answer the cleaner's questions. Dialog: checkbox **Involved people are only on call** in *How it fits in* (`#fOnCall`, tooltip explains; shown while somebody is involved, by default or on some day, R-EVT-21). Effects: in the **clash rule** (R-EVT-10) only the responsible person counts as shared, never the involved ones (*no responsible person* still clashes); in **statistics** the involvement doesn't count, even with *Include time as involved person* **[U]**; box row 2, peek card, agenda and `aria-label` say **On call:** (*De guardia:*) instead of *With:*. The people filter is unchanged.
- **R-EVT-17** **[U]** **Background activities**: an event marked **In the background** (R-EVT-19) is drawn as a **strip** (14 px, event colour) instead of a box **[U]** — the cleaner "just happening" without bothering anyone, or screen-free time. Strips come **only from the mark**: activities of external people (R-PPL-03) are ordinary boxes unless marked; **Rejected:** an automatic rule that made them strips (external responsible person, nobody involved or only on call): it overlapped with the mark **[U]**; data saved under that rule is upgraded (`MIG[3]`, R-DATA-08). Strips sit at the **right edge** of the day column; **[C✓]** a column with strips reserves a gutter (`--gut` on `.day`; 16 px per strip sub-lane) that boxes, margins, stripes and handles stop before, so boxes lose a few pixels rather than half their width; overlapping strips are packed side by side in the gutter (`data-strip="k/n"`). Strips **never take part in lanes or stripes** and never make anything clash (excluded from `laneLayout` before it runs). **Looks like a lip [U]:** the first strip is flush with the column's right edge, right corners rounded and left corners straight (a mirrored phase lip; a piece cut at midnight keeps only its outer right corner rounded), and it shows the **title vertically, reading top-to-bottom** (`writing-mode:vertical-rl`, no rotation; 10 px bold, ellipsis, `textContent`), in `ink()` colour **[U]**. Phase lips deliberately keep reading bottom-to-top **[U]**. The rest (person, times) is in the peek card and `aria-label`; the ⚠ of overlapping repetitions only in the peek card. Flexible start/end shows as a lighter part (gradient) and the title starts where the solid core starts; flexible time is a dashed strip; dashed and all-margin strips use the page text colour. **Background band [U]:** each strip also tints its column for its time window (a child of `.day` inserted before the hour lines `.gl`, so it lies under hour lines, margins, boxes and stripes): the **full event colour next to its strip** (so it joins the strip without a visible step **[U]**) **fading to transparent at the column's left edge** (`linear-gradient(to left, …)`), from `left:0` up to its own strip (`right` = the strip's offset + 14 px, so with several strips each band reaches its own one and runs under the nearer ones); schedule opacity applies; overlapping bands mix; flexible start/end margins are fainter (vertical `mask-image`), flexible-time and all-margin pieces give a half-strength band; dimmed in Phases mode. **Only the lip is interactive [U]:** the band has `pointer-events:none`, so presses, drags, hovers and right-clicks on it act on whatever is beneath (a box, or empty space → create an event); hit-testing never finds a strip outside the gutter. Interaction like any event (hover peek, tap/click opens, drag moves, bottom handle resizes, locked = click-through, inert in Phases mode); hit-testing by x: `laneMap` holds `['s', from, to]` in px from the right edge (sub-lane k owns `[16k, 16k+16)`, so strips and boxes meet without a gap) and `inLane` (which now gets the day) keeps boxes out of the gutter, using the column width `fxAt` measured. An unmarked event is a **normal box** with the normal rules whoever leads it (a babysitter with Lucía clashes through Lucía).
- **R-EVT-19** **[U]** **In the background** (`event.bg:true`, only when set; per event; *En segundo plano*; not *Doesn't keep anyone busy*, since it also covers the cleaner, who is busy **[U]**): for things that happen **without keeping the household busy** — the cleaner at work, or *screen-free time* for Olivia 18:00–20:00 while she still does homework, has dinner and a bath (this was the parked *non-obstructive tasks* idea; chosen over a separate kind of item "rules/conditions" and over phases with people **[U]**). A marked event is a **background strip** (R-EVT-17; it is now the only way to get one **[U]**) **whoever leads it** — one of our people, an external one, or nobody (= the whole family) — with its people kept as usual **[U]**: no lanes, stripes or clashes, never nested and never a host (R-NST-01); the people filter applies as to any event. **Purely informational** (no warnings about activities during it) **[U]**. **Left out of the statistics entirely** (for every person, also as involved time) **[U]**. Dialog: a checkbox in *How it fits in* (R-UI-07), under the nesting one, **In the background (doesn't keep the household busy)** (*En segundo plano (no ocupa a los de casa)*, `#fBg`, tooltip with screen-free time and the cleaner as examples; strips are *tiras* in Spanish, never *franjas*, which are phases); while it is ticked the nesting checkbox is disabled (the tooltip says why). Hover card, agenda and the strip's `aria-label` add *In the background*; the strip's label says *By:* only when somebody is responsible, *(external)* only for external people, and *With:* unless the involved people are on call. A help tip (help18) describes it; help15 and the *External* menu tooltip point to it.
- **R-EVT-20** **[U]** **Owner of an event** (Fair Play's *CPE*: conceive, plan, execute — the partner who holds the whole task, even when someone else does it on a given day): `event.owner` (a person id, optional **[U]**; only **our people** can own an event **[U]** — an owner who later becomes external is kept and shown as such). The **responsible person of an occurrence** (`slot.person`) is whoever **performs** it; it defaults to the owner: a day marked **Owner** (`slot.fo:true`) **follows the owner** — choosing another owner moves all of them, while a **stand-in** (a named person) stays **[U]**; `slot.person` always holds the effective performer (`parseData` and every owner change keep `fo` days at `owner || ''`), so **clashes, lanes, stripes, statistics and the people filter are unchanged** and keep using the performer **[U]**. Without an owner, *Owner* days are performed by nobody until one is chosen. Deleting the owner leaves the event unowned (its *Owner* days keep following); insert and schedule transfers map the owner through the people mapping. Hover card, agenda and `aria-label` add **Owner: Ann** (*Titular:*). **Upgrade (format 5, `MIG[4]`):** each event gets as owner its most frequent performer among our people (ties: the earliest repetition), and the days they perform become *Owner* days; events performed only by external people or by nobody stay unowned.
- **R-EVT-21** **[U]** **Involved people per day:** `event.involved` is the **default** list and a day can have its **own list** (`slot.inv`, stored only when it differs from the default; `[]` = nobody that day) **[U]**. The effective list (`invOf(e,s)`) is what clashes, nesting hosts, the people filter, statistics and every label use. Edited with the day's **With** button (R-UI-07); deleting a person removes them from the days' lists; insert and transfers map them. *Only on call* (R-EVT-16) stays event-wide and applies to whichever list is in effect.
- **R-EVT-22** **[U]** **A colour per repetition** (`slot.col`, only when set; events only, never phases **[C✓]**): absent = the **event's colour** (the default); `'p'` = the **performer's colour**, following the performer (a new performer or a recoloured person recolours the box; nobody performing → the event's colour); `'t'` = the **activity type's colour** (R-EVT-11), following the type (a recoloured type, another type or a deleted one → the event's colour when there is none) **[U]**; `'#rrggbb'` = **a colour of its own**. `colOf(e, s)` is the one place that resolves it, and everything the occurrence draws uses it: box, flexible margins, soft look, `--dash`, background strips and their band, the striped mix of overlaps (`it.color`), the hover card chip, Live View bubbles, the day agenda edge and print; the chooser shows it per repetition (event colour when repetitions are grouped). Not affected: the title's swatch (the event's own colour), the Copy dialog's colour options (they act on the event colour; repetition colours are copied as they are), statistics (type colours). Dialog: a **Colour** column in the day table (R-UI-07): a swatch per time showing the colour the box will get (a person icon when it follows the performer, the type's icon when it follows the type; label *Monday: colour: Performer's colour (Ann)*), opening a menu inside the dialog (`cPop`, `.cmenu`: **Event colour**, **Performer's colour (Ann)**, **Activity type colour (Work)** — *(no type, so the event colour)* without a type —, **Other colour…** → the colour picker; the current one ticked); it follows changes of performer, owner, activity type and event colour while open; ⧉ copies it, + and a newly ticked day start with the event colour. No event-level "colour by performer" switch: one day + ⧉ does it **[C✓]**. Format 6 (`'t'`: format 7) (R-DATA-08).

Overlaps, stripes and side-by-side lanes (R-EVT-09, 10, 13, 18, 23) are in `lanes.md`; repetitions in `repetitions.md`.
