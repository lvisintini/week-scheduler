# Phases and rhythms (background day-structure)

- **R-PHS-01** **[U]** A **rhythm** = the regular cadence of a home/workplace over a week (e.g. "Normal rhythm", "Holiday rhythm"); a **phase** = a named part of the day (Sleep time, Lunch time…). (Names chosen by the user over "periods"/"period sets"; Spanish: *franjas* / *ritmos*.)
- **R-PHS-02** **[U]** Rhythms behave a bit like schedules but are separate entities; a rhythm can be hidden but **only one rhythm can be shown at a time**. With a cycle of several weeks a phase can be every week, in some weeks only, or at different times per week, like an event (R-CYC-16). Phases are **always in the background**, drawn as a colour band behind events with the hour lines/borders over it. **One opacity control for all rhythms** (slider in the Rhythms section); the lips are always fully opaque. Rhythm visibility and the opacity are view state (R-UI-05, R-DATA-06).
- **R-PHS-03** **[U]** Phase fields: name, description (optional), colour, ≥1 rhythm; **no people**. Repetitions stay within one day; same day table as events (R-REP-02); a phase can belong to several rhythms and be copied to another rhythm (same Copy dialog).
- **R-PHS-04** **[U]** **Lips:** a vertical-text tab in a lane **outside, to the left of** each day column, its right edge flush with the column's left border. Hover tooltip: name, day range (e.g. `Mon–Fri`), times, description. **Grouping:** if the previous *displayed* column has the same phase with identical start/end, no lip is drawn there; **the lane still shows the phase colour as a translucent band (same opacity setting)** so the colour is continuous across the group. Different timings → each gets a lip. The lane exists (18 px) only while a rhythm is visible.
- **R-PHS-05** **[U]** Phases are never counted as hidden by the hidden weekend or the hours shown (R-GRID-02), and are cut at both ends of the hours shown like anything else.
- **R-PHS-06** **[U]** **Edit mode** switch (sidebar: *Events | Phases*): in Phases mode events are inert and dimmed (35 % opacity, desaturated) and phase repetitions are interactive; in Events mode phases are pure background (lips still show tooltips). Editing one kind can never affect the other. **[C✓]** In Phases mode phase boxes get **dashed borders in their colour**, an inline label (`name · times`), a resize handle, the lip becomes a drag handle, and the grid gets an accent-coloured inset outline as a mode cue. Drag, resize, Shift-single, toast, choosers and right-click Copy work exactly as for events.
- **R-PHS-07** **[U]** **Rhythm agenda** (with a cycle: a phase's week pattern is named under its title, and a phase with different times per week gets a section per week, R-CYC-16) (agenda icon on the rhythm row): phases sorted by earliest start, then grouped into runs of consecutive days with identical times, scanning Monday→Sunday with **no Sunday→Monday wrap** (e.g. `Monday to Thursday 12:00–13:00`, `Friday 13:00–14:00`, `Saturday to Sunday 12:00–13:00`). The day agenda lists the day's events under its phases (R-PRN-04).
- **R-PHS-08** **[U]** **Default first-run rhythm** (also after Clear memory and for a new workspace): a **visible** "Normal rhythm" with **7 parts of the day**, the same times every day, no descriptions: Midnight 00:00–05:00, Early morning 05:00–08:00, Morning 08:00–12:00, Noon 12:00–14:00, Afternoon 14:00–18:00, Evening 18:00–21:00, Night 21:00–24:00 (Spanish: Madrugada, Primera hora, Mañana, Mediodía, Tarde, Atardecer, Noche). **Rejected:** activity-like phases (Sleep time, Work/School time, Free time…), which the user found confusing **[U]**. The boundaries and names were proposed by Claude and confirmed by the user **[C✓]**.
- **R-PHS-09** **[U]** **Reordering rhythms:** each rhythm row starts with the same **grip** as people (R-PPL-02, `gripFor(r, S.rhythms, rh, S.rhythms, 'gripRhTip')`; the opacity row has none): drag it or focus it and use the arrow keys. The order is data (undoable, unsaved; no format change). **What the order does** (stated in the grip's tooltip): switching to Phases mode while no rhythm is shown **shows the first rhythm**; a new phase goes into the first rhythm when none is shown; it is the order of the rhythms in the phase dialog and the Copy dialog. Which rhythm is shown stays view state (R-PHS-02).
- **R-PHS-10** **[U]** **Lip text shrinks for short phases:** a lip's name is 10 px; when it does not fit the lip's height it becomes **8 px** (`.s1`), and when that does not fit either **7 px** (`.s2`), before the ellipsis cuts it; a lip **under 12 px tall shows no text** (`.s0`). The full name, days, times and description stay in the lip's tooltip. Measured in the browser after the boxes are fitted (`fitLips`): every lip is measured before any of them changes, one layout per step, as for event boxes (R-EVT-05). A printed day view sizes its lips at the print scale (its lips drawn from bands take the classes of their group's lip, `data-fs`).
