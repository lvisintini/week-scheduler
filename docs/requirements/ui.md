# Sidebar, settings, dialogs, theme, icons

- **R-UI-01** **[U]** All controls live in the sidebar (no header). Title with the favicon on its left at the top. Sidebar is collapsible (chevrons), its width adjustable (drag edge, 230–560 px), and the grid uses the free space. The **top row** (favicon, title, help, gear, chevron) **stays at the top while the sidebar scrolls** (`.sbtop` sticky, with the card background) **[U]**: on a phone the chevron used to scroll out of reach. **Collapsed**, the sidebar is a 46 px rail holding, top to bottom, the **›** that opens it, a **Live View** button (`#lvR`, camera icon; red with a stop icon while live; R-GRID-12) and, at the bottom, the **gear**, away from the chevron (it was pressed by accident on a phone) **[U]**. Under 600 px the top-row buttons are at least 44 × 44 px, with gaps. State saved in prefs.
- **R-UI-02** **[U]/[C✓]** Layout (user approved): top row = favicon, title (• when unsaved), help `?`, settings gear, collapse chevron; workspace switcher button (name, • if unsaved, menu), Events|Phases switch, icon toolbar = **+** (new event, or new phase in Phases mode; accent coloured, tooltip also mentions dragging) **[U]**, undo, redo, save, load, print, statistics (R-STAT-01); Events|Phases switch; collapsible sections **Schedules**, **People**, **Activity types** (R-TYP-01), **Rhythms** (count, ⓘ tip, + button), **Tools** (R-UI-11, with the **Live View** row, R-GRID-12) and, last, **Zoom** (ⓘ tip only; R-GRID-07) **[U]**; slim rows (eye, coloured icon — click = colour picker, editable name, lock badge, ⋯ menu); every name field has an accessible name (*Name of the schedule* / *person* / *rhythm*; types: *Activity types*).
- **R-UI-03** **[U]** **Settings dialog** (gear): **three tabs** **[U]** — *View* (early hours, now line, AM/PM, hide weekend), *Data* (Restart, Clear memory), *UI* (**theme: System / Light / Dark**, full-width switch, and **language**; grouped because both start from the browser's settings) **[U]**; every option has an explanation. Tabs look like tabs (underlined active tab, no boxed button group; arrow keys switch) and the **dialog keeps one size**: all panes share one grid cell and inactive ones are `visibility:hidden` + `inert`, so the largest tab sets the size **[U]**. The last tab used is shown again while the page stays open (`setTab`, not saved). **Nothing about zoom is in Settings** — it lives in the sidebar **[U]**. Designed to gain more tabs later. **Help dialog** (`?`) lists usage tips **[C✓]**.
- **R-UI-04** **[U]** Colour pickers: popover with swatches, HSL sliders, hex field and an **Apply** button (Enter also applies, Esc cancels) — used everywhere instead of `<input type=color>`.
- **R-UI-05** **[U]** Undo/redo (buttons + Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z, 100 steps). **[U]** Visibility (eyes of schedules, people, activity types and rhythms), opacity and view settings are *view state*: not undoable, not "unsaved changes". Lock *is* data.
- **R-UI-06** **[C✓]** Toasts: 2.2 s plain, 7 s with action buttons. Day agenda dialog has **Print agenda** (list) and **Print day view**.
- **R-UI-07** **[U]** **Event dialog layout — a sectioned form** (chosen by the user from three mock-ups, replacing one long column of labels): `#dlg` is 760 px wide; fields sit in a **label column** grid (`.fg`, 92 px labels tied with `for=`), which folds to labels-above-fields under 560 px. **Only real values appear at event level** **[U]** (the former *By* list, *Timing* switch and *All days* general times only set every day and looked like event settings; they are gone). Top (no header): *Title \** + colour swatch (named *Colour*) in one cell, *Description*, *Activity type* (icon + list). **Who** (`.fsec` header with a rule): **Owner** (`#fOw`: *(none)* and our people, a person icon; the tooltip explains Fair Play's conceive-plan-execute, R-EVT-20), **With** = the default involved people (our people only, never external ones) as **toggle chips** (`.chips`: each chip is a label holding a real, visually hidden checkbox; ✓ and accent when ticked, focus ring). **When**: the day table (R-REP-02) with a header row (*Days · Start · End · Performed by · With · Colour · Timing*; explanations in the tooltips), the Mon–Sun rows and their further-time lines. **Each time** (`rowCtl`/`rowSub`): start, end, **Performed by** (*Owner (Ann)* — follows the owner, the default —, *Nobody (concerns everyone)*, or any person, external ones marked), a **Colour** swatch (R-EVT-22), a **With** button (`.wbtn`: *Default* greyed, following the event's list, or the day's own names; it opens `wPop`: *Use the event's list* switch + our people's chips), a **Timing** list (`.tsel`, R-EVT-15) with the margins on a line of its own under the row (`.dsub`), on a day row a **⧉** button that **makes every other ticked day like this one** (R-REP-02; toast *Copied to the other days*) and a **+** (another time on that day), on a further-time line a **✕**, and the ⚠ of overlapping repetitions. Day rows and further-time lines are `display:contents` inside one grid (`#paneQ`, columns in `--dc`, time columns ≥ 68 px), so columns line up; each line's first cell restarts at column 1. **A long list of times scrolls inside the table** instead of making the dialog grow **[U]**: `#paneQ` is at most `min(420px, 50vh)` high with its own scroll bar, the header row stays put (sticky cells; three empty header cells and their shadows cover the ⧉/+/⚠ columns and the gaps; under 560 px the whole `.dhd` is sticky), and a time added with **+** is scrolled into view. **Under 560 px** each line is its own small grid (named areas): day, start, end, ⧉, + or ✕ / performer, With, ⚠ / timing, colour / margins; an unticked day is one line. **How it fits in** (`#fFit`): the event-wide switches together — *Involved people are only on call* (shown while somebody is involved, by default or on some day; its value is kept), *Can be done during the person's other activities*, *In the background*. **Schedules \*** (or **Rhythms \***) as chips; *at least one* is in the tooltip and the error. Footer above a rule: Delete / Copy… / Cancel / Save. Long explanations live in tooltips, not labels. Phases: no Who or How it fits in, no performer, With or timing; phase end times stop at 00:00.
- **R-UI-08** **[U]** **Light/dark theme** toggle in Settings (System default = follows `prefers-color-scheme`; Light/Dark force it via `data-theme` on `<html>`; colours are CSS variables, dark values duplicated in the media query and the `[data-theme=dark]` rule). The muted grey `--mut` (hour labels and other secondary text) has at least 4.5:1 on `--bg` and `--card` in both themes (light `#636b7d`). Text on an accent background (primary buttons, the selected Events | Phases button) uses `--onacc`: white in light mode, `#0d1220` in dark mode, where white on the lighter accent was only 2.9:1. Per browser (prefs), never in the save file; printing is always light.
- **R-UI-09** **[U]** Icons: calendar icon for schedules, user icon in the person's colour for people, the chosen built-in icon for activity types (R-TYP-02), calendar favicon (inline SVG).
- **R-UI-10** **[U]** **The event/phase dialog can be dragged aside** to look at the boxes it hides: by its **grip bar** (`#dGrip`, `.dgrip`: a full-width strip of six dots at the top, `cursor:move`, tooltip explaining dragging, the arrow keys and the reset) or by **any empty part of the dialog** (not fields, labels, buttons, chips, the day table or the menus inside it: `DLG_NODRAG`). Mouse and touch (pointer events; `touch-action:none` on the grip); the focused grip moves it **20 px per arrow key**. The grid behind **stays dimmed** **[U]** (the backdrop is unchanged). Placed with `left`/`top` (`dlgPlace`, class `moved`), **not a transform**, so the fixed-position menus inside the dialog (colour, With, colour picker) keep their viewport coordinates; at least 120 px of it and its grip bar's height stay inside the window. **Every open puts it back in the middle** **[U]**.
- **R-UI-11** **[U]** **Tools** (*Herramientas*): a collapsible sidebar section **after Rhythms, before Zoom** **[U]** (`secTools`, ⓘ tip) for Live View and temporary ways of looking at the week; **every switch is remembered by this browser** **[U]** (prefs); the switches here and in Zoom are **sliding toggles** **[U]** (real checkboxes with `role="switch"`, drawn with `appearance:none`: a `--mut` track, `--acc` when on, a white knob that slides; focus ring; no animation under `prefers-reduced-motion`; the Settings dialog keeps plain checkboxes), none of them is data (no undo, no unsaved mark). It holds, in this order: the **Live View** row (`#lvB` / `#lvC`, R-GRID-12; folded with the section); **Highlight events without an activity type** (`prefs.hlNoType`): the boxes and strips of untyped events get a **pulsing red outline** (`.noty`, an `outline` so it never fights the selection's box-shadow; a still outline under `prefers-reduced-motion`; never printed); **Colour by activity type** (`prefs.colBy='t'`) and **Colour by person** (`'p'`, the performer), which **exclude each other** and temporarily draw **every occurrence** in its type's or its performer's colour, **grey (the statistics' *No type* colour, `NOTY`) without one** — through `colOf`, so boxes, margins, strips, stripes, hover card, Live View, agenda and print all follow. The stored colours are untouched: `colRaw` resolves them (R-EVT-22) and the event dialog's swatches keep showing them. Last, **Fixed lanes, one per person** (R-EVT-23).
- **R-UI-12** **[U]** **Opening a repeating event from the grid shows the clicked repetition:** a click or tap on an occurrence (also via the chooser, which passes the repetition picked or under the pointer) opens the dialog with that time's line (a day row or a further-time line; `o.src`/`x.src` remember each line's slot, `dlgJump`) **scrolled to the middle of the day table only when it is not fully visible** below the sticky header **[U]**, and the line **pulses once** (`.dr.pulse`, about 1.4 s, accent background and ring on its cells; a still highlight under `prefers-reduced-motion`; the class is removed after 1.6 s). Only for events and phases with more than one repetition; **+** and creating by dragging open no line.
- **R-UI-13** **[U]** **Phone-sized windows** (narrower than 600 px, `phone()` = `matchMedia('(max-width:600px)')`; phones are for checking a schedule, §1): the sidebar is a **drawer**. It **starts closed whatever was saved** (`prefs.collapsed` is set at startup, not saved); opened, it lies **over** the grid (fixed, full height, `min(90vw, sidebar width)`, shadow) above a dimmed backdrop (`#sbBack`) that closes it on a tap, so the grid keeps the full width; the resize edge is hidden. Closed, the rail of R-UI-01 stays. A phone **opens on today's day view** (R-GRID-11; `focusD = today()` at startup unless Live View is remembered, which wins): a second exception, after Live View, to "focus is not remembered"; ◀ ▶ and **Week** work as usual. **Swiping sideways in the day view changes the day** on any touch screen (left = next, right = previous, wrapping and skipping a hidden weekend like ◀ ▶): it counts when the finger starts moving within the long-press time (so a long-press drag never swipes), goes more than 60 px and over twice as far sideways as up or down, and did not start within 24 px of the screen edge (the browser's back gesture); never in Live View; the day view's columns are `touch-action:pan-y` (`#grid.fo`), since nothing scrolls sideways there. Desktop windows are unchanged.
