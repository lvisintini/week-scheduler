# Product

Static files served as they are by GitHub Pages: `index.html`, `app.css` and ES modules in `js/` (vanilla JS, no libraries, no build, no network requests; R-CODE-01). **[U]** Opening it from disk is no longer a requirement: GitHub Pages is how it is shared (locally, `npm run serve`). This made the strict script policy of R-SEC-01 possible. A weekly planner (a workspace may repeat over a cycle of 2–4 weeks, still without dates) organised in **workspaces** (several independent named data sets in one browser), each with overlayable **schedules**, **events** with repetitions, **people**, and background **rhythms** made of **phases** (named parts of the day). English/Spanish UI. **[U]** It serves households and workplaces alike, and its descriptions, tooltips and help say so (R-I18N-02). Repo files: `index.html`, `app.css`, `js/`, `img/help/` (the pictures of How to use, R-UI-17), `README.md`, `CLAUDE.md`, `docs/` (the specification, code map, testing notes, parked items, known issues), `tests/` and the dev tooling (`package.json`, `playwright.config.js`, `.github/workflows/`).
- **R-CODE-01** **[C✓]** **The code is ES modules** (asked for as the parked step towards real boundaries between the files, and towards TypeScript or React later): `index.html` loads one script, `<script type="module" src="js/main.js">`, and every file imports by name what it uses from the others (`import {…} from './x.js';`, one line per file, at the top) and exports what they use, so a missing name stops the page from loading (and fails `npm run lint`) instead of failing later. **The state that several files share is one object, `state`** (`js/state.js`, the only file without imports): the data (`state.S`, `state.WS`, the undo stacks…) and the view state (`state.prefs`, `state.curWk`, `state.focusD`, `state.live`…); state that one file owns stays private to that file. **[C✓]** One object rather than exported variables with setters: one shape to type later and one place to observe changes from (a store), and `state.curWk` reads as state wherever it is used. **Code at the top level of a file only defines things** (it may read `state`): the files import each other in circles and a browser runs them depth first from `main.js`, so whatever uses another file at startup is in a function that `main.js` calls (`loadPrefs`, `initLive`, `initDialog`). Tests: jsdom, which can't run modules, gets each one as a classic script in the browser's order; the browser tests reach the modules' names through a test-only bridge, never through anything in the app.
- **[U]** **Phones are for checking a schedule, not for building one:** a complex week with people is too much to edit on a small screen, and nobody is expected to. On a phone the app is made pleasant to *look at* (and Live View, R-GRID-12, is the main use); editing stays possible but is not designed for.
