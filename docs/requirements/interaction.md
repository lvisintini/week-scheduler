# Choosing among overlapping things (click vs drag) and touch

- **R-SEL-01** **[U]** **Click** (open dialog): if everything under the pointer belongs to one event (even several overlapping repetitions) the dialog opens directly; if different events overlap, a small list shows each event once (repetitions grouped). "Under the pointer" means the same time *and* the same lane (and the shown week, R-CYC-07): events side by side (R-EVT-10) never trigger a chooser for each other.
- **R-SEL-02** **[U]** **Drag** (move or resize): if more than one event *or repetition* could be meant (bodies for moves; bottom ~9 min for resizes) a chooser lists each repetition separately (with its day/times). **[C✓]** The pick becomes the **selection** (`selK={id,i}`): outlined and raised above neighbours; the next drag that starts where it is a candidate acts on it directly. Esc, a click on empty space, or undo/redo clears it. (Two-step by design: you cannot choose while the button is held.)
- **R-SEL-03** **[C✓]** **The right-click menu** of a day column (`ctxMenu`; the browser's own menu is suppressed): its header names the **place** (*Monday 10:30*, the minute under the pointer snapped down to 15); then **one row per event (or phase, in Phases mode) under the pointer**, locked ones included and repetitions grouped, each with **Copy…** (its Copy dialog) and, for events, a **lock button** (R-EVT-26: *Lock "Work"* / *Unlock "Work"*, `aria-pressed`; disabled when its schedules lock it) **[U]**; and last **+ New event here (10:30)** (*+ New phase here* in Phases mode, R-SEL-04). It also opens on empty space, with only that last row. Esc or a click outside closes it; focus starts on its first button.
- **R-TOUCH-01** **[U]** **Touch (Google-Calendar style, mouse behaviour unchanged):** dragging scrolls natively (`touch-action:pan-x pan-y` on day columns/lanes); a **tap** opens an event (or the chooser if several events overlap); a **long-press (0.4 s, vibration tick)** on empty space starts creating an event, on an event starts moving it, on its bottom handle starts resizing (handle hit area is 16 px on coarse pointers). `press()` implements it; `touchmove` is `preventDefault`-ed only while a long-press drag is active. The native long-press context menu is suppressed; a long press **lifted without moving** opens the app's right-click menu instead (R-TOUCH-02). A wobble under 4 px is not a drag, for creating as for moving.
- **R-TOUCH-02** **[U]** **The right-click menu by touch** (chosen by the user over a Copy item in the tap chooser **[U]**): a long press (R-TOUCH-01) on an event — or on a phase in Phases mode — that is **lifted without moving** opens the same menu as a right-click (R-SEL-03: Copy…, the lock, + New event here) instead of finishing a zero move or opening the dialog. **Locked events too** **[U]**: they let the finger through to the column (R-SCH-02, R-EVT-26), so a long press there that is lifted without moving opens the menu when something is under the finger (the touch way to unlock an event), and creates nothing. A long press on empty space lifted without moving still starts a new event; a long press that moves still moves, resizes or creates; mouse behaviour is unchanged (`touchMenu`, called from `grab`, `startDrag` and `startCreate`). The help and the lock tooltip mention it.
- **R-SEL-04** **[U]** **Creating where editable events are in the way** (a click there opens one and a drag moves it): **+ New event here** in the right-click menu (R-SEL-03; on touch, a long press lifted without moving on the event, R-TOUCH-02) opens a new event at the place's time for an hour, as a click on empty space does (with every week side by side, in that week, R-CYC-19); and on a computer **Alt+drag** (Option+drag on a Mac) on an event, its resize handle or its margins **draws a new event's range** over whatever is there instead of moving it (Alt+click: an hour from there), the event left untouched (`grab` hands it to `startCreate`). The + button's tooltip and the help mention both. A locked event (R-EVT-26) lets clicks through, so locking what is in the way also works. **Rejected:** a *Create* mode switch that makes every event click-through (a mode you forget is on), and Alt+drag alone (nothing for touch, hard to discover) **[U]**.
