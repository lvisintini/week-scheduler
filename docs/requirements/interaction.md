# Choosing among overlapping things (click vs drag) and touch

- **R-SEL-01** **[U]** **Click** (open dialog): if everything under the pointer belongs to one event (even several overlapping repetitions) the dialog opens directly; if different events overlap, a small list shows each event once (repetitions grouped). "Under the pointer" means the same time *and* the same lane (and the shown week, R-CYC-07): events side by side (R-EVT-10) never trigger a chooser for each other.
- **R-SEL-02** **[U]** **Drag** (move or resize): if more than one event *or repetition* could be meant (bodies for moves; bottom ~9 min for resizes) a chooser lists each repetition separately (with its day/times). **[C✓]** The pick becomes the **selection** (`selK={id,i}`): outlined and raised above neighbours; the next drag that starts where it is a candidate acts on it directly. Esc, a click on empty space, or undo/redo clears it. (Two-step by design: you cannot choose while the button is held.)
- **R-SEL-03** **[C✓]** Right-click on a day column lists events/phases under the pointer → Copy dialog.
- **R-TOUCH-01** **[U]** **Touch (Google-Calendar style, mouse behaviour unchanged):** dragging scrolls natively (`touch-action:pan-x pan-y` on day columns/lanes); a **tap** opens an event (or the chooser if several events overlap); a **long-press (0.4 s, vibration tick)** on empty space starts creating an event, on an event starts moving it, on its bottom handle starts resizing (handle hit area is 16 px on coarse pointers). `press()` implements it; `touchmove` is `preventDefault`-ed only while a long-press drag is active. The native long-press context menu is suppressed; a long press **lifted without moving** opens the app's Copy list instead (R-TOUCH-02). A wobble under 4 px is not a drag, for creating as for moving.
- **R-TOUCH-02** **[U]** **Copy by touch** (the touch equivalent of right-click Copy, R-SEL-03; chosen by the user over a Copy item in the tap chooser **[U]**): a long press (R-TOUCH-01) on an event — or on a phase in Phases mode — that is **lifted without moving** opens the same list as a right-click (*Copy event…*, each event or phase under the finger once) instead of finishing a zero move or opening the dialog; picking one opens its Copy dialog. **Locked events too** **[U]**: they let the finger through to the column (R-SCH-02), so a long press there that is lifted without moving opens the list when something is under the finger, and creates nothing. A long press on empty space lifted without moving still starts a new event; a long press that moves still moves, resizes or creates; mouse behaviour is unchanged (`touchCopy`, called from `grab`, `startDrag` and `startCreate`). The help and the lock tooltip mention it.
