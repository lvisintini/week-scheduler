# Calendar grid

- **R-GRID-01** **[U]** Columns Monday→Sunday, left to right. Days are **not** attached to dates (it's a repeating week; a workspace may repeat every 2–4 weeks, and the grid then shows one week of the cycle, R-CYC-01/04 — still without dates).
- **R-GRID-02** **[U]** Hourly rows from 05:00 to midnight by default; 00:00–05:00 hidden but can be shown (Settings → "Show early hours"). Events/phases in hidden hours are kept; they count in the "N hidden" badge (events only).
- **R-GRID-03** **[U]** **Saturday and Sunday: only the header cells have a different hue** (not the whole column). The hue covers just the header cell *between the day column's borders* — it must not extend into the phase-lip lane on the left, **except** the lane between Saturday and Sunday (both weekend headers), which takes the same hue so the two headers read as one band (the lane between Friday and Saturday stays neutral; the single-day print drops the join). Dark-mode variant exists.
- **R-GRID-04** **[U]** Settings: show/hide Saturday & Sunday columns; AM/PM clock; show/hide a red **now line** on the current weekday's column (updates every 30 s, default on, never printed; with a cycle of several weeks it is drawn only in today's week once this browser knows it, and in whatever week is shown until then, R-CYC-05).
- **R-GRID-05** **[U]** Midnight is always displayed as `00:00` (`12:00 AM` in AM/PM mode), never `24:00`.
- **R-GRID-06** **[C✓]** 48 px per hour by default (the *Row height* default; *Fit height*, on by default, sizes the rows to the window, R-GRID-07), 15-minute snapping, hour lines, sticky day headers. Each day header shows an **agenda icon**; clicking the header opens that day's agenda **[U]** (of the shown week, R-CYC-12). The top-left corner cell holds the week switcher when the cycle is longer than one week (R-CYC-04). **Narrow week columns** (under 70 px, from the grid width measured before the grid is emptied — a layout of the empty grid would reset the scroll position; e.g. a phone) get a **short name** (*Mo Tu We Th Fr Sa Su* / *Lu Ma Mi Ju Vi Sá Do*, full name as `aria-label`) without the agenda and focus buttons (they would sit on top of the names); **a tap opens that day** (R-GRID-11), whose header has the agenda **[U]**.
- **R-GRID-07** **[U]** **Zoom (grid scale and grid text size):** the sidebar's **Zoom section** (collapsible like the others, `secZoom`; never in Settings **[U]**; sliders have `aria-label`s, explanations are tooltips) holds, in this order **[U]**: **Fit width** (`fitW`, default on) with the **Column width** slider indented under it (px per day, **70–1000**, default 110), **Fit height** (`fitH`, default on) with the **Row height** slider under it (px per hour, 24–120, default 48), a divider, **Text size** (`txt`, 80–160 %, step 10, default 100), and *Reset zoom* (both boxes on, 48 px, 110 px, 100 %). **Fit width** on = the columns share the window width (40 px minimum, scroll sideways below that); off = each column is **exactly** the slider width (a narrower week leaves empty space on the right, a wider one scrolls sideways — that is how to make room for side-by-side lanes, R-EVT-10). **Rejected:** *Fill the window width* ("at least the slider width, stretched"): every value below window ÷ 7 looked the same **[U]**. **Fit height** on = rows sized so the visible hours fill the window height under the **measured** day header (it grows with the text; measured before the grid is emptied, since a layout of the empty grid would reset the scroll position; no layout → the slider value). A slider is **disabled while its Fit box is on and shows the fitted size** (`updZoomUI` after every render), and **unticking keeps that size** so nothing jumps **[C✓]** (a focused day is not a week column: unticking *Fit width* there keeps the slider value). **Text size** sets `--ts` on `:root` and `#grid`; grid text uses `calc(Npx * var(--ts,1))`: box text and its icons (and the room kept for the status icons), hour labels, day names, phase labels, the hover card and the Live View sizes (multiplied, R-GRID-12); the time column is `round(52 × ts)` px. **Lips and strip titles keep their size** (fixed-width lanes); the sidebar and dialogs never scale — that is the browser's zoom **[U]**. **A phone-sized window has its own row height [U]** (600 px wide or less, R-UI-13): *Fit height* and *Row height* there read and set `fitHP` (default **off**) and `rowHP` (default **100 px per hour**, about 7 hours on a phone screen, so boxes are big enough to tap), so the computer's 48 px and fitted rows never squeeze a phone (all the visible hours in a phone's height were ~35 px per hour, too small to tap); *Reset zoom* there goes back to that (its tooltip says so), and the *Fit height* tooltip explains it. **A phone also has its own width [U]:** *Fit width* and *Column width* there use `fitWP` (default on) and `colWP` (default 110 px), and **Fit width follows the view**: a day view (startup, a short day name, ◀ ▶, a swipe, Live View) turns it on, the week view turns it off and keeps the column width, so the week scrolls sideways at that width; ticking or unticking it by hand lasts until the next switch of view; *Reset zoom* there goes back to on and 110 px. Per-browser prefs (`rowH`, `colW`, `fitW`, `fitH`, `rowHP`, `fitHP`, `colWP`, `fitWP`, `txt`; the retired `fillW`/`fit` are no longer read); recomputed on window/sidebar resize while a Fit box is on; changing zoom keeps the view centred on the same spot; **printing ignores zoom and text size** (48 px / 110 px / 100 % via `withPrintScale`). Zoom affects only the calendar grid — the sidebar (and its narrow-screen behaviour) is deliberately unchanged **[U]**.
- **R-GRID-08** **[U]** **Scrolling:** the time column and the day headers are sticky (the top-left corner cell is sticky both ways) and the grid's scrollbars are always visible (`overflow:scroll`, styled scrollbars). `100dvh` is used so mobile browser bars don't hide the bottom of the grid. The grid's scroll area (`#wrap`) is **one tab stop** (`tabindex=0`, `role=region`, *Week grid (arrow keys scroll)* / *Cuadrícula de la semana (las flechas la desplazan)*, set in `setLang`) with a focus ring on keyboard focus only (`:focus-visible`), so the arrow keys and Page Up/Down scroll it. **Firefox** draws the scrollbars as the operating system says (overlay scrollbars that appear only while scrolling under Windows 11's and macOS's defaults): no CSS can force classic ones there, so in Firefox *always visible* depends on the OS setting (*Always show scrollbars* / *Show scroll bars: Always*); Chromium and Safari follow the styled `::-webkit-scrollbar`.
- **R-GRID-09** **[U]** An **"N hidden" pill** (bottom-right of the grid) counts only event occurrences that are not shown *purely because* they fall in the hidden early hours or on the hidden weekend. Occurrences that are even partially visible (e.g. 04:00–06:00, or Fri 22:00 → Sat 02:00 with the weekend hidden) are never counted, and neither are occurrences hidden by the people filter or a hidden schedule; with a cycle of several weeks only the shown week counts (R-CYC-12). Tooltip gives the weekend / early-hours breakdown; click opens Settings. Never shown in Live View (R-GRID-12).
- **R-GRID-10** **[C✓]** Layer order in a day column: phase backgrounds → background-activity bands (R-EVT-17) → hour lines (drawn *over* phases, **[U]**) → events → overlap stripes (in the day column, over the boxes' colours, under all event text) → nested boxes (R-NST-02) → now line.
- **R-GRID-11** **[U]** **Focus on one day** ("laser focus"): each day header has a **focus button** (viewfinder icon, at the header's right; **shown on hover** and on keyboard focus, always on touch screens, so it doesn't make the day names wrap; tooltip *Show only Tuesday…* explains the way back); clicking the day name still opens the agenda (R-GRID-06). In focus only that day is drawn, **filling the window width** even with *Fit width* off (the row height, *Fit height* and text size still apply). The header shows **◀ day name ▶** (wrap around Sunday→Monday — with a cycle of several weeks into the next week, and the header adds the week, R-CYC-04 —, skip Saturday and Sunday while the weekend is hidden) and a **Week** button that brings the week back, as does **Esc** when no event is selected (Esc first clears a selection; ignored while a dialog or menu is open). **[C✓]** View state that is **not remembered** (a reload shows the week; the exceptions are Live View, R-GRID-12, which has no arrows, Week or agenda buttons, and a phone-sized window, which opens on today's day view, R-UI-13), not undoable, not an unsaved change. The **N hidden** pill counts only the focused day's occurrences in the hidden early hours. **Print** prints what is on screen: the day view while focused, the week otherwise; the focus buttons never print. Everything else works as usual (create, move, resize, peek, choosers); moving an event to another day or resizing into the next day's column is not possible in focus — use the dialog. A help tip describes it.

Live View (R-GRID-12) is in `live-view.md`.
