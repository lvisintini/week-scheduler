# Activity types

- **R-TYP-01** **[U]** A workspace-level list of **activity types** `{id,name,color,icon,soft?}` managed in its own collapsible sidebar section **Activity types** (between People and Rhythms; count, ⓘ tip, + button; `secTyp`). Purpose: a later **per-person weekly statistics dialog** showing how each person's week is allocated **[U]**. Row: a grip (R-TYP-05), an eye (R-TYP-04), the type icon in its colour (click = **icon grid** of the built-in set), editable name, ⋯ menu (*Colour…*, *Icon…*, *Soft look* toggle with a tick and an explanatory tooltip, *Delete*). Each row has an **eye** (R-TYP-04). **+** asks for a name and starts with the plain dot icon. Delete asks for confirmation, naming how many events lose the type; those events become untyped. Types are data (undoable, mark the workspace unsaved). Colour is **for statistics** **[U]**, and for the repetitions that choose *Activity type colour* (R-EVT-22).
- **R-TYP-02** **[U]** **Built-in icons only** (no emoji, no uploads) **[U]**: `TICONS`, 45 inline line-SVGs in the app's icon style (moon, bed, sun, cutlery, cup, pot, briefcase, school, book, pencil, computer, target, clock, broom, clothes, shopping, tools, home, water, smile, heart, health, medicine, exercise, ball, bicycle, car, bus, trip, people, talk, phone, TV, games, music, art, photo, pets, plant, outdoors, star, goal, money, gift, dot), each with an English and Spanish name (tooltips and `aria-label`s of the grid). CSP-safe (shapes only). **Defaults** (new workspace, first run, Clear memory; localised, renameable) **[C✓]**: Sleep (moon), Meal (cutlery), Work/School (briefcase), Focus time (target), Chore (broom), **Free time (sun, soft look)**, Social (people) **[U]**, Personal care (water), Travel (car), each with its own colour.
- **R-TYP-03** Types travel with the workspace (browser memory, files, links; anonymised exports keep type names, like schedule names). `parseData`: names ≤ 200 chars, hex colours, unknown icons → `dot`, `soft` only when `true`, an event's `type` is dropped when it references no type; import limit **100 types**. **Insert into the current workspace** and **copy/move a schedule to another workspace** match types **by name (case-insensitive)**, creating missing ones — no mapping dialog, unlike people **[C✓]**; a schedule transfer brings only the types its events use.
- **R-TYP-04** **[U]** **Show/hide activity types:** each type row has an **eye** (`types[].visible`, saved with the workspace like a person's eye, default shown; the row gets `.off` when hidden). Hiding a type takes **its events off the grid** (boxes and strips), out of hit-testing, the day agenda and Live View, and they don't host nested activities on the grid — it is one more grid filter in `slotVisible`, so it reaches exactly as far as the people filter: **events without a type are always shown** **[U]**, **the statistics are unchanged** (they count everything) **[U]**, and hidden-type occurrences are not counted in *N hidden* (R-GRID-09). View state (R-UI-05): not undoable, not an unsaved change, ignored by `dataKey()`, kept across undo. Types created by **+**, an insert or a transfer start shown. Format 8 (R-DATA-08).
- **R-TYP-05** **[U]** **Reordering activity types:** each type row starts with the same **grip** as people (R-PPL-02, `gripFor(row, S.types, t, S.types, 'gripTyTip')`): drag it or focus it and use the arrow keys. The order is data (undoable, unsaved) and is **the order of the statistics** (168-hour bar, day bars, table, CSV and clipboard columns, the *Everyone* legend; *No type* always last) **and of the event dialog's *Activity type* list** **[U]**. No format change: the list order was always stored.
